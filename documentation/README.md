## 📖 Documentation Guidelines

### When to Use Each Document

**Starting a new feature?**
→ Check `FEATURES.md` and `FEATURE_STATUS.md` to see what exists

**Need to understand AI features?**
→ Read `AI_FEATURES_IMPLEMENTATION.md`

**Working with GraphQL?**
→ Refer to `GRAPHQL_IMPLEMENTATION.md`

**Understanding booking flow?**
→ Review `BOOK_NOW_FLOW.md`

**Quick command reference?**
→ Use `QUICK_REFERENCE.md`

**Setting up the project?**
→ Start with `../README.md`

**Implementing a new feature?**
→ Create a spec in `../.kiro/specs/`

## 🔄 Keeping Documentation Updated

When making changes to the platform:

1. **Update relevant documentation** in this folder
2. **Update feature status** in `FEATURE_STATUS.md`
3. **Add entry to activity log** in `activity-log.md`
4. **Create/update specs** in `../.kiro/specs/` for new features
5. **Update README.md** if setup process changes

## 📝 Documentation Standards

- Use Markdown format for all documentation
- Include code examples where relevant
- Keep documents focused and concise
- Use clear headings and structure
- Include links to related documents
- Update timestamps when making changes
